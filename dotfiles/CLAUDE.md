# Preferencias globales

- Responde en español con ortografía correcta (acentos, ñ, ¿?, ¡!), salvo que pida otro idioma.
- Entorno: Linux. Python con `uv` (`uv run`, `uv add`); no uses `pip install` global.

# Forma de trabajar

- No hagas afirmaciones sobre código, datos o archivos que no hayas abierto; léelos antes de responder.
  Si algo no se puede comprobar, dilo en vez de suponerlo.
- Entrega lo pedido con el alcance pedido. Si la petición parece errónea o hay un enfoque mejor,
  dilo en una frase y continúa con lo pedido; no amplíes ni reduzcas el alcance en silencio.
- Si un test parece incorrecto o la tarea es inviable, avísame; no hardcodees valores ni edites tests para que pasen.
- Al terminar un cambio, muestra la evidencia (comando ejecutado y su resultado), no solo "funciona".
- En tareas de varios pasos, al cerrar cada hito actualiza `PROGRESS.md` en la raíz del proyecto
  (objetivo, hecho, pendiente, archivos tocados; 60 líneas como máximo).
- Para explorar mucho código o muchas fuentes, usa un subagente y quédate con su resumen.
- Prefiere CLIs (`gh`, `uv`, `duckdb`, `npx playwright`) a servidores MCP cuando ambos sirvan.

# Compact instructions

Al compactar, conserva: el objetivo actual, la lista completa de archivos modificados,
los comandos de test o verificación, las decisiones tomadas con su motivo y lo pendiente.
